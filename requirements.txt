# The GitHub repo's package name is "nari-tts" even though the importable module is "dia".
#
# PINNED, deliberately, to the last commit before nari-labs' 2025-06-27 refactor
# ("New weights & transformers support", 65028e0c). That refactor changed how the
# model computes while KEEPING every parameter name identical, so cosrigel's weights
# load "cleanly" (343/343 keys match) onto the new code and then quietly degenerate:
# a 68-char sentence ran 1331 decode steps / 15.5s instead of ~300 / 3.3s, looping
# fragments instead of stopping at EOS. On this pinned commit the same input gives
# 301 steps / 3.3s. The model card confirms base_model: nari-labs/Dia-1.6B (the
# pre-refactor repo). Do not bump this without re-testing generation length.
nari-tts @ git+https://github.com/nari-labs/dia.git@4a9e29b1bd

# 1.5 or newer, and the floor is load-bearing on Windows. Under 1.0 the hub lays the

# opened by anything on this machine — the download reports success and the model load
# dies several steps later with "Could not parse the architecture config". 1.x does not
# use them. diareader/hf_cache.py repairs it if it ever comes back.
huggingface_hub>=1.5

# The quality checker transcribes each generated sentence and counts the syllables it
# recognised (diareader/asr_verify.py). transformers 5 is deliberate rather than
# incidental: the only reason this project was ever pinned to 4.57 was a second TTS
# engine that has since been removed, and that pin dragged huggingface_hub below 1.0
# with the cache bug above. The recogniser is a 95M-parameter wav2vec2 CTC model, runs
# on the CPU in ~0.2s a sentence and never touches the GPU — Whisper was tried here
# once and removed because loading it beside Dia took the process down with a CUDA OOM.
